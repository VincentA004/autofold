# Reusable biology and protein-design skills for Autofold

Research date: 2026-10-10. Read-only investigation of the main checkout at `/Users/vincentallam/Developer/autofold` and public primary sources. No skills/plugins were installed, no source was changed, and no model inference, weight download or GPU work occurred. Source text, metadata and test files were downloaded only into `/private/tmp/autofold-skill-source-audit`.

## Recommendation

There are worthwhile premade procedural skills beyond the five BioNeMo-derived capsules. The best immediate additions are **experimental design**, **target/construct preparation**, **statistical evidence interpretation**, and **metric units/uncertainty**. Use K-Dense's maintained scientific collection for the first, third and fourth, and Google DeepMind's science-skills plus K-Dense's UniProt/RCSB guide for target preparation. Extract scientific decisions and failure modes into Autofold's immutable knowledge format. Do not import their execution instructions or plugin/hook machinery.

For miniproteins, selectively expand epitope-selection, generation/validation coupling, interface diagnosis and diverse selection from K-Dense and current NVIDIA Complexa skills. For 12–16-residue macrocycles, the premade `rfpeptides-macrocycle` skill is a useful index, but it is insufficiently faithful to cyclic validation to import directly. Author the adapted guide from the official RFpeptides protocol and cyclic ColabDesign notebook, with the community skill as secondary provenance. No inspected collection establishes an experimentally validated, end-to-end LLM guide for this exact cyclic PD-L1 objective.

“Well-tested” must be scoped: public test suites can demonstrate parsing, numerical properties, wrapper behavior and package contracts. They do not establish binder discovery, molecular chemistry fidelity through Autofold, or improvements caused by adding an LLM skill. The recommendations below are candidates for adoption and controlled evaluation, not accepted scientific improvements.

## Reuse hazards found in actual content

1. **Cyclic wrapper examples can generate linear output.** devxia's RFpeptides skill examples invoke a standard wrapper without cyclic flags, then note that it may not support them and recommend direct invocation or updating the wrapper. It proposes AF3/Boltz-1 or OmegaFold validation without showing topology-preserving inputs. Extracting this as an executable recipe would violate Autofold's required chemistry round trip. Use the official flags and ring-offset validation sources; reject unsupported predictor chemistry before dispatch.

2. **Metric conflation is explicitly tested in one upstream suite.** K-Dense's binder-filter test accepts `pae_interaction` among ipTM aliases. Its script contains the same alias mapping. That field name alone cannot establish metric equivalence; PAE and ipTM differ in semantics and units. Never inherit this alias in Autofold's typed metric layer. See [script](https://github.com/K-Dense-AI/drug-discovery-agent-skills/blob/2bd3bdec5b724f8715a5c2ff828d82245b3a5a6a/skills/protein-binder-design/scripts/binder_filter.py).

3. **Glycan removal needs biological context.** K-Dense's binder skill advises removing glycans/disorder because the tools do not model them. Its target parser tests skip glycans. This is a representation limitation, not permission to expose a physiologically occluded site. Preserve full-target/glycan identity and compare assay-specific constructs; crop only with reversible numbering and full-target steric checks. Its [filtering reference](https://github.com/K-Dense-AI/drug-discovery-agent-skills/blob/2bd3bdec5b724f8715a5c2ff828d82245b3a5a6a/skills/protein-binder-design/references/filtering-and-validation.md) is useful for separating self-consistency from binding evidence, but absolute thresholds require campaign calibration.

4. **Cross-validator confidence can reproduce the present faulty agreement.** devxia's [cross-validation](https://github.com/devxia/protein-design-skills/blob/3a52d655bd6f2b67ce4921671656a4559558f0a2/skills/cross-validation/SKILL.md) averages confidence-style fields and presents agreement as higher confidence. It also suggests monomer-first cascades and broad runtimes/model assumptions. Do not adapt its aggregation or mandatory monomer cascade. Compare identical molecular inputs, target-aligned poses/interfaces and metric-specific uncertainty; sample rejected candidates to audit false negatives.

5. **Computational “success” and negative controls need relabeling.** NVIDIA's [validation guide](https://github.com/NVIDIA-BioNeMo/bionemo-agent-toolkit/blob/4f1b6a49a6b1d7cbbbc569a1d5e7b26a46bcb9a8/workflows/generative-protein-binder-design/protein-binder-design/references/validation.md) is explicit about in-silico benchmarking, but calls filter pass fraction success rate and shuffles negative controls. In Autofold use computational filter yield and assumed/derived controls, reserving experimentally bound/nonbinding labels for provenance-backed assays. This also avoids scripts/eval assertions teaching stronger claims than the evidence supports.

6. **Tool permission frontmatter is not scientific authority.** Upstream `allowed-tools: Bash` and instructions to edit target configs, create home-directory credential files, install packages, invoke hosted APIs or manage GPUs are irrelevant to domain capsule admission. Remove them and any implicit threshold/evaluator authority. Preserve the task reasoning without the upstream host behavior.

## Concrete adaptation and acceptance plan

1. **Import as attributed candidates, not active facts.** Create at most four foundational capsule candidates first, with exact source paths/commits and license notices. Preserve all five current parents. Keep related model-selection extensions small to avoid conflicting generic guides.
2. **Translate to native Proto reasoning.** Each capsule should define applicability, prerequisites in evidence, allowed decisions, diagnostic handoffs, failure modes and falsifying questions. It can advise proposing graph changes permitted by a frozen contract. It cannot invent tool keys, run shell/API code, install anything, grant tools, mutate target identity/evaluator/budget or report a trusted score.
3. **Add evidence prerequisites.** Target preparation needs canonical construct/site/residue mapping; macrocycles need explicit atom-level bonds/stereochemistry and supported adapter declarations. Missing fields lead to an uncertainty or unsupported-capability result, not sequence-only fallback. No monomer fold-confidence requirement for flexible bound peptides without modality-specific evidence.
4. **Evaluate guide behavior cheaply first.** Use fixed CPU fixtures and serialized scientific cases: repeated prediction rows counted as independent molecules; equal confidences/different poses; missing metrics; pTM/ipTM/iPAE substitutions; circular optimization/evaluation; ring rotations; silent linearization; crop/glycan occlusion; shuffled controls asserted known nonbinders. Check the agent's decisions and evidence labels, not keyword matching alone.
5. **Use controlled replay for adoption.** Parent and candidate receive identical frozen context, evaluator, model configs, sample selection and budget. Pin hashes, independent candidate identities and seeds. Report invalid recovery separately from gains on valid pairs. Follow actual Autofold acceptance policy; sufficient repeats and cross-campaign generalization matter. Do not change the evaluator to make a guide pass.
6. **Keep scientific validation separate.** A guide that improves valid diverse computational yield is useful, but experimental binding, specificity, correct chemical identity/purity and PD-1/PD-L1 competition still require assays. A new chemistry-capable execution lane requires separately authorized model setup and bounded GPU assessment; this research authorizes none.

The first practical batch is `experimental-design-and-replication`, `target-construct-and-epitope-preparation`, `comparative-evidence-interpretation` and `measurement-semantics-and-uncertainty`. The modality decision then determines whether the next batch is a ring-aware macrocycle guide or miniprotein epitope/interface/diversity extensions. Importing an entire collection would add substantial unrelated context and conflict with Autofold's execution boundary.
