This audit covers execution preparation, local/remote process control, verified scientific receipts, scientist evaluation intents, and deterministic closeout. ## Lifecycle and authority map

1. `ScientistLane.evaluateTrial` admits a bounded prospective request, captures authored bytes, validates its native declaration, writes a lifecycle checkpoint, then fsyncs `scientist.json` with the complete intent. Request identity is bound to captured bytes; edited drafts need a new request. The store and scientist file are separate authorities, so the durable origin `(jobId, phase)` is required to make trial creation replay safe.
2. `ResearchService.createTrial` uses a store transaction. Existing exact origin bindings are replayed; a different declaration fails. New managed admissions now require the exact caller epoch, active ancestor chain, original deadlines, matching scientific scope, and active campaign. Standalone synthetic origins with no job record remain supported because existing direct lanes use them. Caller authority is ephemeral and is not copied into immutable scientific origin identity.
3. `ScientificExecution.evaluateOnce` prepares source/evaluator/target/native declarations, writes a temporary run directory with copied inputs, bundle, and immutable request; fsyncs files and publishes the whole directory with one rename. The deterministic `runId` binds project and request. The external execution index is advisory: request recovery falls back to the published `request.json` in the run directory.
4. `executeRecord` reserves one store run under the exact binding. A replay reuses it. Preflight is replay safe readiness/staging, followed by an exclusive fsynced `dispatch.json`, then the advisory index advances to dispatching. The fence conservatively consumes local dispatch authority even if a controller dies before spawn.
5. Both built-in transports now invoke `Dispatch.authorizeStart` before their first scientific launch. Preparation completes first; the final managed ownership check reads one current store snapshot and requires the original caller's lease epoch, cancellation state, live ancestor chain, original deadlines, and active campaign/experiment. The current epoch is supplied by ScientistLane or the shadow controller, not loaded from a replacement owner.
6. Remote launch uses another exclusive fsynced host attempt file, then the remote supervisor exclusively creates `remote-receipt.json` in `launching` state before detaching a controller. These two files answer different questions: host attempt means SSH may have been sent; remote receipt means the remote launch identity was accepted. Missing remote receipt after any host attempt remains unresolved.
7. The remote controller starts one scientific worker, writes `running` with PIDs, enforces its own monotonic timeout and cancellation file, waits for process termination, then publishes a final receipt. Provider/cloud/SSH credentials are removed from the worker environment. Shutdown or lease loss detaches the host without cancelling the scientific process; explicit cancellation requires actual remote acknowledgement if a host launch was attempted.
8. Remote status retries only read-only connection/timeouts, never launch or cancellation. Terminal success retrieves the output tree into a temporary host directory, checks tree shape/count/size, then publishes output. Receipt success is operational authority, not a score. Recovery now observes this terminal receipt even when a local manifest already exists.
9. `readVerifiedRunReceipt` verifies complete bundle/program/target/evaluator/contract/run/trial identities, fixed seeds and candidate bounds, generation and scoring indices, per-artifact hashes, manifest hashes, and persisted manifest hash on later reads. A verified manifest alone cannot override a remote timeout, cancellation, or failure.
10. `completeRun` atomically commits evaluation, run success, trial terminal status, incumbent decision, and evaluation knowledge. Duplicate finalizers now replay only the same manifest and normalized evaluation; disagreement fails with `run_receipt_conflict`.
11. Scientist closeout uses per-run trusted actor identity to ingest one deterministic knowledge cycle/search observation, publish derived knowledge, append the trusted event, write the full result file, save the compact request result, and finish lifecycle checkpoints/feedback. All are replayable, but span store and filesystem. A closeout failure leaves the intent pending and retries its original run, not new compute.

## Verified defects fixed in this pass

- **Remote manifest bypassed operational terminal outcome.** Former `execution/index.ts:514–518` returned successful finalization as soon as a host manifest existed; no transport observation occurred. This could accept a timed-out run with complete-looking artifacts. Current `reconcileRecord` around line 524 restricts manifest-only recovery to local transport. The new CPU test runs the real mock worker to create valid files, injects a lost dispatch acknowledgement, then reports remote timeout; recovery creates no evaluation and marks the run failed.
- **Replacement epoch could authorize a stale launcher; local launch skipped the final scope guard.** Former remote `authorizeStart` passed only job ID, so the current replacement lease satisfied the check. LocalWorkerTransport never called the callback. Current execution input carries ephemeral `caller:{jobId,leaseId}`; all built-in first launches invoke the final guard, and `assertTrustedJobLease` requires exact epoch. New local regression revokes the experiment in preflight and proves no manifest/evaluation is produced.
- **Cancellation/ancestry/deadline could race trial creation.** A successful lifecycle check did not fence the subsequent `createTrial` transaction. New admission uses the shared snapshot ownership predicate inside the same mutation and applies original deadlines and scientific scope. Parent campaign activity is now checked in that transaction too. Exact existing origin replay remains recovery, not new admission.
- **Concurrent finalizers falsely errored after another owner committed success.** Former `completeRun` required `running` even for identical receipt replay. Current store transaction compares manifest plus normalized evaluator result and returns the existing evaluation/knowledge only when identical. New regression races two execution reconciliation calls, proves one evaluation, and rejects a changed score against the same manifest.
- **Paused scope blocked exact trial-identity recovery.** The existing-origin lookup previously came after experiment-active admission. An already-created trial lost from the scientist file after a crash could not be looked up once its scope paused. Existing exact binding replay now precedes new-work admission checks; a new origin phase still fails. A service regression pauses campaign and experiment and verifies both behaviors.

## Remaining architecture gaps and safer target

1. **Unify local and remote durable supervisor semantics.** Local processes are detached but their timeout and cancellation belong to the host process. There is no durable PID/status receipt or local reconcile implementation. A host SIGKILL removes the timer while the scientific process may survive. Use the same run supervisor protocol locally and remotely; controller-independent process ownership should use a service manager/cgroup where available. Merely saving a PID is insufficient because PID reuse cannot prove identity.
2. **A permanent run registry should own launch arbitration.** Current file exclusive-create fences favor at-most-once safety by leaving multiple unavoidable unknown states. A small transactional registry with `prepared → launch_claimed → running → terminal`, immutable run/input hashes, launch token, controller boot identity and process identity can improve diagnostics. Restarted controllers may observe/adopt existing worker identity, never spawn a replacement while existence is uncertain. Exactly-once external process launch cannot be promised solely by host transactions.
3. **Separate new-work authority from effect reconciliation everywhere.** Launch requires current epoch/deadline/cancellation/scope. Observe, retrieve, verify and deterministic closeout require original run identity and receipts, so expired grants can settle existing effects without permission to generate more science. Persist these transitions explicitly rather than reconstructing from unrelated booleans/file presence.
4. **Persist the execution implementation closure.** Remote staging freezes worker source; local launches still use the live installed worker tree. Reconciliation's `dispatchInput` checks current evaluator source before remote retrieval, even when the remote worker has frozen old evaluator bytes. Keep content-addressed trusted worker/evaluator/runtime manifests with the run; reconciliation should select the originally frozen implementation closure rather than current installation.
5. **Freeze the whole remote plan identity.** The supervisor validates bundle/worker hashes and plan shape, but runtime path, environment overrides and timeout are not part of the receipt identity. A separate plan hash would make launch configuration and wall-time authority attributable and detect plan mutation under an otherwise unchanged run identity.
6. **Treat scientist and derived views as projections of store facts.** `scientist.json`, result files, events, knowledge exports and lifecycle checkpoints span several systems. An append-only store intent/result journal plus a durable projection outbox can regenerate all of them. Current trusted closeout actor identities are useful foundations. Preserve full scientific lineage and amendments; never rewrite a recovered failure as though it never happened.
7. **Persist bounded unresolved diagnostics.** A running receipt with dead controller currently looks the same as temporarily unreachable live compute. Expose `controller_unreachable`/`process_identity_unknown` as observational states without manufacturing scientific failure or releasing reservations. Provide an explicit operator evidence reconciliation path for truly lost process identities.
8. **Separate job cancellation from settled effects.** `jobs.cancel` makes the job terminal immediately and `controller.reconcile` returns terminal jobs unchanged. Its scientific run may still await remote cancellation acknowledgement or provider accounting. The existing unresolved-run exclusion correctly blocks replacement compute, but a terminal cancelled job can retain stranded original effects. Add a durable effects/accounting settlement projection for cancelled jobs; keep canonical cancellation intact while read-only reconciliation settles the original receipts. A cancelled run must not create scientific-failure knowledge.
