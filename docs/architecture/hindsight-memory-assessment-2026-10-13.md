# Hindsight memory for Autofold

Research date: 2026-10-13. Hindsight is a plausible advisory retrieval layer for Autofold, provided its results remain subordinate to Autofold’s canonical evidence, provenance, and execution controls.

## Recommendation

Autofold can use Hindsight to improve selective retrieval over prior decisions, failures, hypotheses, and procedural history. It could replace parts of the *retrieval implementation* behind advisory context, especially semantic search and broad relationship discovery. It should not replace Autofold’s canonical source inventory, decision-memory projection, receipt checks, frozen target or evaluator, experiment-scoped knowledge records, Pi session archive, or execution and accounting controls.

The right architecture is a host-owned adapter that indexes approved immutable exports, returns candidate source references, and requires Autofold to resolve and validate each source before it reaches a scientist. Hindsight facts, observations, mental models, and synthesized answers are derivative context. They cannot establish measurements, change a score, authorize work, or settle costs.

This recommendation incorporates the [memory-library investigation](memory-libraries-investigation-2026-10-12.md), which compares Hindsight with OpenViking and describes Autofold’s append-only experiment journal, native Pi archive, frozen guidance, and replay restrictions. Hindsight is worth evaluating for historical decision retrieval; its automatic coding-agent integration is a separate product path with capture, injection, and update behavior that should not be mixed into a controlled campaign.

## Hindsight’s memory model

Hindsight stores information in isolated memory banks. `retain` accepts content and divides it into chunks. Its extraction modes include LLM-based fact extraction and a `chunks` mode that stores text without extraction. With extraction enabled, Hindsight derives facts, time and entity data, and relationships, then indexes them for recall. Chunk retention avoids the extraction-model call, though a chosen embedding provider may still incur work or cost. Retained documents and memory facts are separate concepts: a document can remain stored and still produce zero searchable memories. Hindsight documents zero-fact retains as successful, so the ingestion path must inspect the resulting memory count. Extraction can also be nondeterministic for borderline content. [Retain and extraction modes](https://hindsight.vectorize.io/developer/retain), [retain API](https://hindsight.vectorize.io/developer/api/retain)

With extracted memories, Hindsight supports entity, temporal, semantic, and causal links. It distinguishes world facts from agent experiences, consolidates related memories into observations, and can maintain mental models or knowledge pages. Observations preserve supporting memory IDs and evidence excerpts, but remain synthesized beliefs over their input memories. Entity resolution uses fuzzy names and co-occurrence, which creates a risk of merging distinct entities. Autofold’s run IDs, program hashes, contract hashes, source hashes, and metric names must therefore remain exact host data rather than inferred entities. [Retain](https://hindsight.vectorize.io/developer/retain), [observations](https://hindsight.vectorize.io/developer/observations), [mental models](https://hindsight.vectorize.io/developer/mental-models)

`recall` runs semantic, BM25 keyword, graph, and temporal retrieval, combines and reranks results, and can include original chunks and source facts. A returned relevance score is a rank signal rather than an absolute probability. Temporal windows affect ranking; they do not restrict results to the specified interval. For cutoff enforcement, Autofold must use a frozen allowed-source set and verify each returned reference locally. [Recall API](https://hindsight.vectorize.io/developer/api/recall), [retrieval overview](https://hindsight.vectorize.io/developer/retrieval)

`reflect` is an agentic answer-generation operation. It autonomously retrieves from the bank, reasons over retrieved memories, and returns a synthesized answer. The current API supports low, mid, and high budgets, optional structured output, source citations in `based_on`, token usage, and traces of tool and model calls. The `max_tokens` setting limits the final answer, not what the loop retrieves. A structured output can fail while the markdown answer still succeeds; a retrieval-tool failure can instead fail the reflect request. On context overflow, reflect can synthesize from the evidence it has gathered. These semantics make reflect useful for exploration but unsuitable as a canonical scientific projection or an unbounded replay-time lookup. [Current reflect API](https://hindsight.vectorize.io/developer/api/reflect)

## Native Pi and coding-agent integration

Hindsight’s maintained coding-agent integration supports Pi and can capture session transcripts, recall or synthesize memory into a session, ingest repository history, and maintain knowledge pages. The current integration documentation describes a per-repository bank by default, shared by linked worktrees. It writes sessions back automatically, and its defaults can inject a low-budget reflect synthesis on the first prompt. Retrieval-only injection modes are also available. The integration’s bank, write-back, and injection settings are configurable, but using it would still change Pi’s default memory and context behavior. It is not equivalent to adding a library dependency or using Hindsight as a read-only index. [Coding-agent integration](https://github.com/vectorize-io/hindsight/tree/main/hindsight-integrations/coding-agents), [integration configuration](https://github.com/vectorize-io/hindsight/blob/main/hindsight-integrations/coding-agents/README.md)

The integration’s `retainExtractionMode` includes `chunks`, which stores text without extraction. Its documentation also states that session write-back occurs at each stop; extraction mode affects those retain costs, and verbose mode uses several times as many tokens as concise mode. Automatic consolidation and mental-model refresh may add background work. The integration can automatically update its installed runtime; the current default is to check for and stage a newer runtime in the background. For a controlled Autofold experiment, automatic capture, injection, consolidation, and runtime updates all need to be pinned, disabled, or moved outside the experimental path. [Integration settings](https://github.com/vectorize-io/hindsight/blob/main/hindsight-integrations/coding-agents/README.md)

There is a concrete recovery concern worth treating as an acceptance criterion. A coding-agent issue reported that the stop hook advanced its session cursor after the server accepted an async retain, although the operation later failed; a subsequent append could leave missing turns in the stored session. The issue links to a fix merged on 2026-10-12. The merged change writes the full Pi branch rather than only the latest run, waits briefly for in-flight shutdown write-backs, and tracks accepted operation IDs so failed or cancelled retains can trigger a full replacement. That recent fix addresses the reported paths, but it reinforces why Autofold must retain its own Pi archive and test ingestion recovery rather than relying on memory-service write-back as the archive. [Issue #5251](https://github.com/vectorize-io/hindsight/issues/5251), [merged fix #5508](https://github.com/vectorize-io/hindsight/pull/5508)

## Storage, operations, costs, and security

The open-source self-hosted path uses PostgreSQL with vector and full-text indexes; embedded pg0 is documented for development. Hindsight’s current storage page specifies PostgreSQL 15+ and pgvector 0.5+, while its installation page says PostgreSQL 14+ and lists additional vector extensions. The supported minimum is therefore inconsistent across current official pages and should be confirmed before a production deployment. The full API image needs about 1.5 GB minimum / 2 GB recommended RAM for local embedding and reranking; the slim image needs about 512 MB / 1 GB but requires external embedding and reranking services. The installation guide says 2 vCPUs are adequate for development/basic workloads and identifies local reranking as a production bottleneck that may benefit from a GPU. PostgreSQL is listed at 512 MB minimum / 1 GB+ recommended. [Storage](https://hindsight.vectorize.io/developer/storage), [installation and hardware](https://hindsight.vectorize.io/developer/installation), [models](https://hindsight.vectorize.io/developer/models)

On 2026-10-13, Hindsight announced **Memlake**, an object-storage memory engine available through Hindsight Enterprise; the announcement says most Hindsight Cloud organizations already run on it. It keeps memory data and indexes in a customer-controlled S3/GCS/S3-compatible bucket while retaining operational metadata, jobs and audit data in PostgreSQL. Its advertised benchmarks report sub-100 ms p99 recall at large scale, but the post identifies some figures as extrapolated or modeled, excludes LLM and embedding/reranker GPU cost from modeled cluster totals, and reports that small banks may cost about the same on Postgres. It is not the open-source self-hosted backend described in the storage docs. Hindsight says its open-source version stays on Postgres. For Autofold’s expected experiment-scoped corpus, this enterprise feature does not change the initial recommendation to evaluate the open-source retrieval path first. [Memlake announcement and benchmark methodology](https://hindsight.vectorize.io/blog/2026/10/13/memlake)

LLM, embedding, and reranker providers are configurable, including local choices. Cloud offers a managed, usage-based option. Costs and latency for Autofold cannot be estimated from product descriptions alone; they depend on source volume, extraction mode, provider, retrieval depth, model, and reflect budget. Self-hosted Postgres can use its normal backup/restore strategy. Memlake describes optional log replication and daily point-in-time snapshots to a separate bucket; that backup feature is part of the enterprise Memlake design. A general canonical export mechanism was not established in the reviewed API documentation, so Autofold should keep its own source archive and rebuildable index map. [Storage](https://hindsight.vectorize.io/developer/storage), [operations](https://hindsight.vectorize.io/developer/api/operations), [Memlake backups](https://hindsight.vectorize.io/blog/2026/10/13/memlake)

Retain may be synchronous or asynchronous. Async work has operation status and retry paths. A client-supplied operation ID makes a repeated async submission resolve to the same operation rather than enqueueing another one, according to the API contract. This does not prove that a failed operation incurred no provider work or spend before failure. Async calls may not return usage metrics directly, so Autofold would need to persist operation IDs, terminal statuses, and any available provider usage or cost records in its own accounting view. Test failure and retry paths for repeated provider work, attribute actual usage where possible, and leave unknown cost explicitly unknown. An index retain must be treated as a derivative projection operation, separate from scientific model requests and compute grants. It must never be counted as a GPU evaluation. [Retain API](https://hindsight.vectorize.io/developer/api/retain), [operations](https://hindsight.vectorize.io/developer/api/operations)

Hindsight supports document IDs for traceability, raw chunks for context, and source-fact IDs for observations. It supports replacing or appending document content, deleting documents or memories, and deleting entire banks. Replacing a document removes its earlier memories. Therefore, use immutable document identities per Autofold source revision, and maintain the source-to-document mapping in Autofold. Do not rely on the memory bank as the archive or rollback source. [Documents API](https://hindsight.vectorize.io/developer/api/documents), [memory APIs](https://hindsight.vectorize.io/developer/api/retain)

Bank isolation, tenant extensions, metadata, and tag filters offer useful controls, but Autofold should bind the bank ID to the authenticated project and experiment on the host. Tags are a retrieval constraint, not a replacement for access authorization or source validation. Hindsight documents an opt-in per-bank memory defense policy that scans for secret and PII patterns; it should not be assumed enabled by default. The core repository is MIT licensed; Cloud processing and service terms are separate from the code license. [Extensions and tenancy](https://hindsight.vectorize.io/developer/extensions), [memory defense](https://hindsight.vectorize.io/developer/security/memory-defense), [license](https://github.com/vectorize-io/hindsight/blob/main/LICENSE)

Hindsight is actively developed. On this research date, its Memlake launch post called the open-source project Hindsight 1.0 and said the API was stable, while GitHub’s Releases page still listed `v0.10.2` as the latest release tag. Treat the version promise and tag mismatch as a pinning detail to resolve before adopting a client or server. Product benchmark results and the paper address agent-memory retrieval benchmarks; they do not establish better scientific decisions, Autofold provenance preservation, or safe frozen replay. [Release list](https://github.com/vectorize-io/hindsight/releases), [Memlake / Hindsight 1.0 announcement](https://hindsight.vectorize.io/blog/2026/10/13/memlake), [ACL 2026 demo paper](https://aclanthology.org/2026.acl-demo.27/)

## Autofold components and the replacement boundary

Autofold’s current memory path has several separate roles:

| Autofold component | Appropriate Hindsight role | Must stay authoritative in Autofold |
| --- | --- | --- |
| `DecisionMemory.project` and source manifest | Hindsight can be a secondary index over its approved exports. | Snapshot scope, hash inventory, revision delta, cutoff, selected facts, interpretation labels, coverage gaps, and bounded packet. |
| `prepareDecisionMemory` | Hindsight can surface likely relevant source IDs. | Receipt/artifact verification, original run-to-trial lineage, raw-evidence availability, and frozen score semantics. |
| `CampaignKnowledgeReader` lexical query | Could be supplemented or partly replaced by Hindsight recall for semantic matching. | Campaign and contract checks, applicability labels, record hashes, exact citations, and authority descriptions. |
| `ProjectKnowledgeGraph` and campaign graph | Hindsight can add broad semantic/entity/temporal associations as an advisory retrieval index. | Autofold’s typed records, exact identity relations, graph snapshot hash, bounded traversal, and distinction between structural evidence and interpretation edges. |
| Scientist reviews, hypotheses, literature claims, and synthesis | May be indexed and recalled as attributed context. | Their source status, revision, evidence references, contradictions, and explicit statement that interpretation is not measurement. |
| Procedural guides and skill versions | Search can help find a candidate guide. | Frozen version ID/content hash, replay validation, applicability, activation, and any permission to use a procedure. |
| Pi session transcripts and archive | May be copied into a separate advisory bank under an explicit policy. | Native SQLite session archive, branch/event history, message paging, compaction ranges and hashes, and archive recovery. |
| Canonical trial/run/evaluation, operation/effect ledger, receipts, grants, and billing | No authority transfer. A derivative index may refer to these records. | Frozen experiment contract, verified worker receipts, dispatch boundary, compute grant, job/effect state, provider accounting, and settlement. |

In the code, [science-core decision memory](../../backend/science-core/src/research/decision-memory.ts) builds a deterministic packet from a scoped snapshot. Its manifest separates evidence, interpretation, and guidance hashes; it records removed and changed sources, unresolved gaps, and the canonical evidence revision. It selects runs before raw artifact reads, admits verified or canonical-commit results with distinct provenance labels, and preserves unverified scores as historical rather than measured evidence.

[The engine adapter](../../backend/engine/src/decision-memory.ts) reads a bounded snapshot and verifies receipt artifacts against stored run manifest and trial program hashes. It publishes the manifest and expansion views as derivative files. The packet’s exposure record is only produced after actual full delivery is acknowledged. [Scientist context](../../backend/engine/src/scientist/context.ts) treats graph calls as advisory and verifies campaign/experiment scope. [Campaign knowledge](../../backend/engine/src/knowledge/index.ts) and [project graph](../../backend/engine/src/knowledge/graph.ts) are read-only views of persisted records, not separate evidence authorities.

Thus, Hindsight is a candidate for replacing a retrieval *engine*, not Autofold’s memory contract. The main replaceable pieces are token/semantic ranking and optional discovery of non-obvious relationships. The canonical ledger, domain-scoped graph semantics, and bounded context assembly should remain the authority and validation layer. A Hindsight retrieval result becomes an input only after Autofold resolves its source ID and confirms the source hash, scope, contract, cutoff, and permission to expose it.

## Proposed adapter and frozen-input rules

Define a host-owned `ScientificMemoryIndex` interface with operations equivalent to `retain(sourceEnvelope)`, `recall(query, frozenSourceSet, limits)`, `operationStatus(operationId)`, and `delete(indexRevision)`. The Hindsight client and server remain behind this adapter. The index should return source identities and excerpts, not an Autofold `Fact`, `Evaluation`, or authorization decision.

Every retained envelope should bind the project, campaign, experiment, contract hash, original source ID and kind, canonical source hash, recorded/occurred time, evidence layer, and exact run/trial/observation/guide IDs where applicable. Use an immutable Hindsight document ID derived from the Autofold scope plus source ID and source hash, and store the same mapping in the canonical store. Retain chunk text for exact context where useful; use `chunks` mode for the first cost-controlled prototype. If extraction modes are tested, they remain alternate indexes over the same immutable export, not transformations of the source ledger.

For each read, pass the query and frozen source inventory or snapshot tags, then revalidate every returned reference locally. Do not treat Hindsight’s temporal window as a cutoff filter. Do not use shared cross-project banks for replay. Prefer one bank per explicit Autofold scope and one immutable bank/snapshot per frozen replay input, or a strict host-side allowlist that rejects any source outside the frozen inventory. The actual packet delivered to Pi must record the index revision, query, source IDs and hashes, result order, byte count, and response hash. A replay consumes that exact frozen packet; it does not query a live bank again.

Do not use Hindsight `reflect` as an opening-context replacement in the first phase. Start with `recall`, where Autofold can validate each result before assembling the prompt. If `reflect` is tested later, only give it already validated evidence, capture its `based_on` IDs, usage, trace, and output, and record the result as a separate interpretation. A cited Hindsight memory is not a direct citation to canonical evidence until Autofold resolves its bound source.

Ingestion should be triggered only after canonical records commit. It can run asynchronously through an idempotent outbox entry keyed by the immutable source hash. Track submitted operation IDs, terminal statuses, retry count, token usage/cost when available, and unresolved cost otherwise. Reconcile failed/cancelled operations before advancing a per-source index watermark. Keep these index operations outside compute grants and scientific effect accounting, but expose their separate provider cost. Cap query rate, returned items, chunk bytes, and `reflect` budget; avoid any hidden background retain/consolidation in a measured replay. Fail open to the current Autofold packet with an explicit index-unavailable gap; never block or grant scientific work because the memory index is down.

## Migration and evaluation plan

1. **Pin a read-only baseline.** Record current Autofold source manifests and packet hashes. Do not import active or completed campaign records into a hosted service for the first study. Build a synthetic or explicitly approved de-identified fixture with exact source IDs, hashes, contradictory evidence, failures, null/invalid runs, multiple contracts, and guide revisions.
2. **Shadow-index the fixture.** Exercise `chunks` mode first, then extracted retain as a separate option. Use deterministic operation IDs and immutable document IDs. Check source mapping, zero-fact reports, retries, deletion, and complete index-status/accounting reconciliation. No result is delivered to the scientist.
3. **Compare retrieval.** Test current bounded context, Autofold lexical/graph retrieval, and Hindsight `recall` on the same corpus and byte/token budget. Freeze Hindsight version, configuration, embedding/reranker/LLM models, and bank contents for each run. Do not enable native Pi hooks, auto-update, background git/session ingestion, or auto-consolidation in the experimental path.
4. **Run advisory delivery tests.** In a fresh controlled experiment, deliver only locally verified recall results. Preserve the normal frozen target/evaluator, grant, worker receipts, and budget. Record the exact delivered packet and exposure on each decision. Roll back by disabling the adapter; the canonical records remain untouched.
5. **Consider synthesis only after retrieval passes.** Evaluate reflect in a separate stage and record output as interpretation with citations and cost. It must not be used to alter authored evidence, trial validity, scores, metrics, dispatch, grant balance, or replay inputs.

Acceptance tests should measure:

| Area | Measurable acceptance condition |
| --- | --- |
| Retrieval quality | At a fixed output-byte/token budget, improve recall of gold source IDs over lexical/graph baselines; report precision and nDCG as well as recall. |
| Provenance | Every delivered item maps to a current canonical source ID and exact hash; unresolved or deleted source references are rejected and counted as gaps. |
| Scope and replay | Zero sibling-experiment, other-contract, future-source, or unapproved-campaign leakage. Same frozen snapshot and settings produce the same exact allowed-source packet or a declared retrieval nondeterminism failure. |
| Epistemic authority | Zero conversions of hypotheses, scientist interpretations, consolidated observations, or model scores into verified measurements. Contradictions and invalid/failed results remain available and labeled. |
| Receipt and evaluation | Hindsight cannot modify contract hash, evaluator hash, score, validity, run state, or receipt authority; original receipts remain independently verifiable. |
| Async recovery | Simulate lost acknowledgements, duplicate submissions, failed/cancelled retains, process exit, and a retry. Confirm the same operation ID does not enqueue a second operation; inspect provider records for repeated work or spend after partial failure, and do not assume retries are cost-free. No source watermark advances on an unresolved operation. |
| Capture integrity | Preserve complete Pi branch/session transcript across multi-run sessions and compaction; compare indexed chunks to the native archive, including first/last messages and archive hashes. |
| Cost and latency | Attribute retain, embedding, rerank, reflect, database, and recovery costs separately. Report p50/p95 latency and token/cost per query and per retained source. Unknown costs remain unknown, not zero. |
| Deletion and rollback | Delete/reindex a test source and verify stale memory IDs cannot be delivered; disable the adapter and reproduce the original Autofold packet from canonical records. |

The recent campaign record reports eight completed GPU runs and 132 OpenRouter calls. The `read_context` response totaled 56,852 UTF-8 bytes; the model registry accounted for 38,155 bytes, about 38 KB of that total. No fresh `read_context` was recorded, so no `DecisionMemoryExposure` was captured. These measurements support evaluating context size, exposure capture, and memory-service overhead; they do not establish that Hindsight will reduce total tokens or improve a scientific decision. Measure those outcomes on a controlled fixture and a fresh run.
