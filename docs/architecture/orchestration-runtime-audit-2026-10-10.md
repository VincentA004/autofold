## Assessment

The implementation has substantial local safety mechanisms, but the overall layer has several owners and several canonical-looking durable records. A short session lease, an operation guard lease, a native job lease, operation JSON, research state, the SDK session tree, an exact host transcript, execution receipts, and job checkpoints must agree. Each subsystem generally handles its own restart; the missing contract is how a host can recognize the complete operation after the process dies between subsystem commits, without entering the model or reconstructing a grant.

The most consequential runtime gap was unrecorded provider billing uncertainty. It was reproduced and repaired in this task. Previously a provider request could be billed, time out before its final usage, and be represented by a synthetic zero-usage assistant failure. The job/campaign then had no durable fact distinguishing measured zero from unknown spend. This is now explicit and fails closed.

The next architectural step should be a host-owned operation state machine and declarative receipt recovery adapter, with the SDK limited to authoring a proposal. Preserve the existing scientific validators, immutable worker receipts, original budget baselines and exact transcript. Do not replace those with more LLM-driven recovery.

## Reproduced gap and repair

Standalone offline reproduction is `/private/tmp/autofold-runtime-ledger-repro-20261010.ts`. It injects an in-memory stream that ignores AbortSignal and reports $1 after the request has timed out. It does not perform a provider request.

Before the fix, provider entry observed durable turns=0 and no request-dispatch event. After the model deadline the session stored turns=1, cost=0, failed status and empty pending tools. The late final $1 response was discarded. No durable field identified billing uncertainty. A crash immediately after dispatch could also lose the turn debit.

After the fix, provider entry observes durable turns=1 and `model_request_dispatched`. Deadline/abort records `modelRequests[requestId].status = unknown`; known accumulated cost stays intact, and `assertSessionAccountingComplete()` prevents baseline capture, result/accounting settlement and another model run. This does not guess the missing $1 cost. The initial dispatch is conservatively recorded before calling the provider because a process crash at the network boundary cannot distinguish not-sent from sent.

An independent ownership review also exposed reliance on polling rather than fresh host authority at each model boundary. Added `PiRuntimeOptions.authorizeModelRequest` (`runtime/types.ts:120`) for ordinary and compaction requests. Runtime invokes it before intent and again after the durable journal wait immediately before provider invocation. Managed literature, review and skills wrappers combine any supplied hook with native exact-origin/ancestor/deadline `newWork` checks; root and ownership agents wire campaign and jobs respectively. Initial denial yields no intent/turn/provider/scientific effect. If a live host is denied after journaling but before invoking the provider, it proves `not_dispatched`, rolls back the turn debit and leaves reportedCostUsd absent. This is not a fabricated provider zero. A process crash in that same interval lacks the live proof, so recovery retains conservative unknown.

## Remaining gaps / redesign priorities

1. **P1 — Generic handler recovery has no declarative typed receipt contract.** `jobs/index.ts:336-354` historically requires `pi:job:result` for non-campaign receipt-only recovery, although each handler commits native scientific state before writing that result. Kill the process after typed commit and before final handler result: recovery can remain interrupted despite a completed effect. Add handler registration `{run, recover}` with recovery results `complete(result)`, `incomplete(reason)`, `unresolved(identity)`. `recover` gets immutable job/grant identity, read-only stores and receipt inspector; it has no provider, create-session or dispatch capability. Complete means native identity and all model/execution accounting are proven; incomplete allows explicit original-grant continuation elsewhere; unresolved cannot rebudget.

2. **P1 — Operation ownership is an advisory cancellation guard over filesystem state.** `literature/index.ts:77-108`, `skills/controllers.ts:41-68` and `knowledge-review-controller/index.ts:108-123` renew synthetic SQLite guard tokens but `check()` tests AbortSignal and native lifecycle, not an atomic operation revision/guard token at state commit. JSON rename cannot share a transaction with a different lease database. A stalled old controller can race a replacement owner at the check/rename boundary. Native job epoch fencing protects managed scientific commits, but direct standalone operation calls can lack that authority. Move canonical operation phase/state into the same transaction authority as job ownership. Keep JSON as an exported/audit view. Reproduce by injecting an await after `check()` and before rename, expiring guard, acquiring replacement, then releasing old writer; observe file revision regression. Do this only with temporary fixtures.

3. **P1 — Several durability domains must be manually reconciled.** Proposal checkpoint precedes JSON save; scientific commit precedes JSON/result checkpoint; execution receipt precedes runId save. They are deliberate safe-first orderings but leave crash windows. Add a host operation record with explicit authoring, accepted, effect_prepared, effect_unknown, committed, accounting_unknown, settled phases and a durable outbox for external provider/worker effects. Every command uses stable operation/effect ID, immutable payload hash and captured lease epoch. Transactionally commit state+event; recovery reads receipts and applies idempotent settlement.

4. **P2 — Budget semantics are stop thresholds, not hard provider spend guarantees.** `runtime/index.ts:297-298`, `:331-334`, `:460-475` gates on prior reported spend; a single allowed response can exceed remaining cost. Defaults intentionally preserve provider output limit (`runtime/models.ts:11`, runtime tests). Enforce a monetary hard ceiling only through host/provider reservation, or explicitly represent a per-request approved reservation and its maximum liability. Do not claim `maxCostUsd` prevents every overshoot or add an arbitrary output cap as a substitute. Original wrapper baselines/deadlines are already durable and must survive the redesign.

5. **P2 — Exact transcript and SDK tree require ad hoc translation.** `runtime/sdk.ts:8-16` infers import offset from number of message entries; context/native overflow rebuilds projection while host archive preserves dropped failed attempts. Existing tests cover current behavior, but branch identity and message provenance should use stable message IDs/source entry IDs rather than count and JSON equality (`runtime/context.ts:93-98`, `runtime/index.ts:394`). Preserve one immutable transcript/event authority; make SDK tree/projection rebuildable.

6. **P2 — Uncertain tool effect closure is protocol repair, not operational reconciliation.** `runtime/index.ts:125-145` clears the pending map after adding explicitly unknown results; the uncertainty remains in transcript/journal, but there is no typed operation ledger for all host tools. Do not interpret a repaired transcript as proof of scientific settlement. Tool identity should reference the host effect/receipt record; subsequent authoring must wait for host reconciliation when effects remain unknown.

7. **P2 — Recovery needs separately named permissions/capabilities.** A single handler `run()` can author, commit, publish and dispatch; the `recoveryOnly` flag is insufficient if wrappers do not consume it. Separate inspect, deterministic receipt settlement, original-grant continuation, publication rebuild, and new authorized work. Phase ownership/deadline/accounting should be checked by one host reducer, not reconstructed independently in each wrapper.

## Required invariants

- A provider or worker effect has a durable original intent before dispatch and an immutable operation/effect ID.
- A dispatched effect without a receipt is unknown. Unknown cost/effect is never measured zero and never authorizes another grant.
- A stale lease epoch cannot admit a trial, dispatch a worker, commit science, overwrite canonical operation state, or settle accounting.
- Recovery can inspect and settle original receipts without creating a session, calling a provider, replaying an unproven effect or resetting baseline/deadline.
- A successful scientific commit and the complete host result can be reconstructed from native typed identities after any process crash.
- Original payload hashes, source snapshots, target/evaluator/seeds/budget and provenance stay immutable through retries.
- Model summaries are continuity projections; exact scientific receipt/evidence authority remains in original host stores.
- Derivative publication failures do not repeat scientific commits or inference.

## Independent challenge to the proposed architecture

A coordinator that merely wraps current `lifecycle.checkpoint(string, unknown)` calls will centralize names without eliminating the split-brain control state. It must own state transitions and expose typed capabilities with a captured epoch; handlers should supply domain-specific proposal validation and receipt interpretation, not implement lease heartbeats, recursive parent checks, restart grants, cost rebasing and final result stitching themselves.

Keep three distinct roles: operation/job authority authorizes scientific work; session lease serializes transcript writes; worker ownership tracks an admitted external process. They need not be one mutex. What must disappear is the ability of a session/operation guard to confer scientific authority independently of the original job/grant. Operation state must be authoritative in one control transaction, while transcripts and worker artifacts remain separately immutable evidence stores linked by stable IDs.

Proposed migration stages:

1. **Current safety repair stage:** exact native epochs for all mutations/dispatch, common ancestor/deadline checks, fresh provider authority callback, durable billing intent and unknown accounting fence. Typed receipt-only handler adapters close existing restart holes without replacing validators or touching historical stores.
2. **Introduce host operation records:** immutable grant/payload hash, operation ID, captured parent/epoch, budget baseline/deadline and typed phase in the current transactional research store alongside job state. Provide one reducer for allowed phase transitions. Import existing operation JSON/checkpoints once by strict identity/hash validation; make JSON an exported view. Do not require a simultaneous rewrite of every scientific table into SQLite.
3. **Separate authoring and effects:** SDK authoring returns accepted typed proposal under a scoped AuthoringCapability. Host obtains EvaluationCapability, CommitCapability or PublicationCapability only from the coordinator after verifying grant+phase+epoch. Prepare a durable effect intent/outbox before dispatch; adapters return immutable receipts; reducer accepts idempotent settlement keyed by effect ID. Recovery capability exposes only receipt inspection and settlement. Model/runtime adapters and remote workers cannot mint capabilities.
4. **Migrate one handler at a time:** literature first (author, fetch ledger, accepted proposal, ingest, publish), then review, refinement, paired replay and discovery/campaign. Run old and new read-only classification side-by-side on temporary/replay fixtures and compare outcome/cost identities. Remove duplicated wrapper guard/heartbeat only when canonical phase+owner CAS protects every state write.
5. **Complete provider reconciliation and budget semantics:** attach attributable provider request IDs/cost receipts when supported; reconcile unknown without another model request or guessed spend. Define the difference between remaining monetary stop threshold and reserved maximum provider liability. Expose explicit unresolved states in the scheduler/HTTP/UI rather than failing to a generic retryable exception.

A provider network call cannot be transactionally combined with a local research-store write. The honest contract is durable original intent + captured authorization + at-most-once receipt reconciliation, with unknown at the crash seam. Claims of exactly-once execution or guaranteed hard dollar budget without provider idempotency/reservation are stronger than the available evidence.
