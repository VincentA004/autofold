# Discovery continuation boundaries

Autofold owns the campaign's grant and completion policy. Pi owns model turns,
tool calls and session compaction. Proto owns execution of the admitted search
program. A boundary in one subsystem must not silently become a terminal decision
in another.

| Boundary | Required behavior |
|---|---|
| Assistant finishes a prose turn | The job continues within the same cumulative turn, tool, cost and time allowance. |
| A scientist batch consumes its local evaluation allowance | A successful host yield ends the complete tool batch. The campaign can admit another child against its remaining grant. |
| Several tools share one assistant message | A successful terminating host result fences later sequential tools, even when the message also contains ordinary tools. Already invoked parallel effects must settle. |
| Scientist declares scientific completion | A typed reason must cite settled canonical measurements. A fixed validation protocol can reserve completion authority to the host. |
| A job consumes its grant | It completes its bounded assignment without inventing a scientific stop or pausing the campaign. |
| Execution may have launched but settlement fails | Preserve the original effect as unresolved. Inspect its original receipt; do not issue a replacement launch. |
| Cancellation races a result | Revoke new work, then verify the original worker's terminal acknowledgement separately from the job label. |
| Context no longer fits | Compact completed historical groups through bounded visible-text fragments; preserve exact instructions, protocol integrity and retrievable originals. |
| Compaction removes the latest scientific packet | Reproject the exact original named call/result in the model-facing context. A summary or artifact reference cannot establish receipt exposure. |
| A later summary request fails | Retain every earlier request's settled usage and owning job binding; do not publish a partially assembled summary as completed compaction. |

## Context authority

The session archive and original SDK entries remain immutable evidence. The
active context is a derived projection. Summary fragments quote effective visible
history with hashes, call identities and UTF-8 byte offsets; they are historical
data rather than executable tool messages. Hidden backend details and transport
metadata must not become model context through summarization.

The latest configured scientific snapshots retain their original call arguments,
result content and provenance. Reprojection creates no tool intent and executes
no tool. A newer explicit retrieval error supersedes an older valid packet.
Conflicting archive bindings, duplicate active call identities and foreign scope
fail closed. Thin call frames avoid restoring unrelated reasoning or sibling
tool output alongside a needed packet.

An actual settled ordinary inference acknowledges delivery. Merely preparing a
packet, retaining it on disk, producing a summary, or restoring it before a
request does not establish that the model received it. Prospective evaluation
admission still checks the exact decision inference and original receipt hashes.

## Replacement and validation

The unified host summary path replaces the oversized-complete-group exception
and the separate native fast path that mixed byte and token estimates. Bounded
recompression requires measurable shrinkage and keeps per-request accounting.
Raw archives remain available for exact retrieval; summaries carry continuity.

The October 14 repair uses the failed live session as an offline reproduction,
alongside fault tests for mixed-tool yields, renewed child grants, scientific
stops, contradictory execution receipts, Unicode fragmentation, snapshot scope
and partial paid compaction failures. Offline checks establish these software
contracts. A fresh live run must independently establish authoring, generation
inside Proto's search, evaluation, delivered memory and complete trial coverage.

Validation retries retain earlier charges and the original absolute deadline.
Earlier runs and their failed acceptance reports remain evidence; fresh success
does not rewrite their outcomes.
