# Native trial execution

Fresh Proto trials export `build_trial(ctx)` returning `ProtoTrial`. Declare one `search=NativeSearch(...)` or `fixed_control=NativeFixedControl(...)`. The native `Program.run()` and base `Generator.sample()` remain unchanged; custom registered generator implementations use Proto's `_sample()` seam. See [native search](examples/native_search_trial.py) and [fixed control](examples/native_fixed_control_trial.py).

`NativeSearch` separately bounds proposals, sampling calls, registered API requests, wall time and the final selected candidate pool. Registered requests include cache lookups; they do not measure physical inference or GPU utilization. `NativeOutput` selects an exact construct, optional segment and lane. The candidate pool can exceed the locked evaluator's final Top-N. Budgets reject excess work before its native effect instead of modifying optimizer or generator parameters.

`NativeFixedControl` is available for calibration and negative-control intent. It freezes the exact explicitly selected protein pool and the full native graph. It permits no sampling or registered requests, including during result extraction. Control intent can use `NativeSearch` when the study requires an actual bounded search. The frozen host evaluator alone owns final measurement.

Every fresh CPU or GPU bundle carries `nativeExecution` independently of a scoring pipeline, including the exact admitted descriptor, explicit outputs, finite search/worker wall ceilings and scoring reservations for every actual candidate, seed and model. It also binds the worker source tree. The worker reconstructs and compares the native program under bounded construction denial, then retains observation through output selection, history and generation provenance capture. Only copied JSON results leave that scope. The host process deadline remains necessary for blocking native kernels. These boundaries do not prove arbitrary authored Python safe.

`build_program`, `AUTOFOLD_TRIAL`, `AUTOFOLD_WORKFLOW`, extraction hooks, diagnostic DAGs and worker portfolio allocation wrappers are historical interfaces. Their adapters are isolated under `autofold_worker/compatibility`; fresh admission rejects them. Original prepared requests execute their own frozen worker and runtime identity and reconcile their original receipts. They are never reinterpreted using the current worker.

Fresh execution requires the actual scoped native lifecycle fork: sampling, request, program-guard and retained hosted-fence API versions must all be 1 and match the pinned source origins. Native PortfolioProgram owns one canonical independent lane sequence, validates its current scientific object graph, and records lane failures. Python frame monitoring and the worker portfolio executor are isolated historical compatibility.

The native closed process fence remains active between construction/execution scopes and after pure capture until disposable child exit. Registered evaluation requests retain exact request/parent identities and actual cache origins under a whole-call deadline covering cold hydration, model execution and native serialization. Model receipts carry runtime.requestObservation; native-requests.json retains before-call intents when terminal publication is uncertain. Cancellation/publication loss stops execution without a scientific retry. Cache origins and request reservations do not establish physical GPU work; that requires separate live telemetry.
